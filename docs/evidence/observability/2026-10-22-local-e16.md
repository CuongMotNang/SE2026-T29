# E16 local drill — independent readiness probe

- **Date:** 2026-10-22
- **Owner:** Vũ Thành Công
- **Branch:** `docs/task-006-observability-evidence`
- **Environment:** Docker Desktop 4.96.2 with WSL2 Ubuntu
- **Scope:** local probe and Prometheus alert verification

## Procedure and result

Only the backend container was stopped. Prometheus, blackbox exporter, Alertmanager and the rest
of the observability stack remained running.

| Event | Observed timestamp / result |
| --- | --- |
| Backend stop requested | `2026-10-22T15:58:08.1512303Z` |
| Probe after 25 seconds | `probe_success{job="booking-api-readiness"} = 0` |
| Alert condition active | `2026-10-22T15:58:22.16191516Z` |
| Prometheus rule state | `pending`, then `firing` |
| Firing observed | `2026-10-22T15:59:47.8511526Z` |
| Backend restart requested | `2026-10-22T15:59:51.8248519Z` |
| Backend ready | HTTP `200` at `2026-10-22T16:00:31.3973205Z` |
| Recovery observed | probe `1`, rule `inactive` at `2026-10-22T16:00:53.4963610Z` |

`ApiProbeDown` fired while the backend was stopped, even though the backend could no longer emit
HTTP metrics. This satisfies the E16 detection path at local-drill scope. The alert automatically
cleared after readiness recovered.

## Limits and follow-up

- The Discord webhook file contains a placeholder, so notification delivery and the resolved
  notification were not verified.
- The blackbox exporter shares the same Docker Desktop VM. It detects an API or readiness
  dependency failure, but it cannot report failure of the whole VM or its network.
- Repeat on the shared Linux demo host and capture Grafana/Alertmanager screenshots for final
  project evidence.
