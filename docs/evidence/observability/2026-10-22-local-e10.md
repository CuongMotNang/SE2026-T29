# E10 local drill — Collector outage does not block booking

- **Date:** 2026-10-22
- **Owner:** Vũ Thành Công
- **Branch:** `docs/task-006-observability-evidence`
- **Verified configuration commit:** `087b6e2`
- **Environment:** Windows, WSL2 Ubuntu, Docker Desktop 4.96.2
- **Runtime:** Docker Engine 29.9.2, Docker Compose v5.6.1
- **Scope:** local rehearsal; this is not the shared Linux demo environment

## Procedure

The stack used the base Compose file, observability overlay and Docker Desktop override:

```powershell
docker compose `
  --env-file deploy/observability.env `
  -f deploy/compose.yaml `
  -f deploy/compose.observability.yaml `
  -f deploy/compose.observability.docker-desktop.yaml `
  stop otel-collector

python -m scripts.smoke_test --base-url http://localhost:8000

docker compose `
  --env-file deploy/observability.env `
  -f deploy/compose.yaml `
  -f deploy/compose.observability.yaml `
  -f deploy/compose.observability.docker-desktop.yaml `
  start otel-collector
```

## Observed result

| Observation | Result |
| --- | --- |
| Collector stopped | `2026-10-22T15:49:46.4392955Z` |
| Smoke test started | `2026-10-22T15:49:50.8342549Z` |
| Smoke-test duration | `0.13 s` |
| Smoke-test exit code | `0` |
| Booking flow while Collector was down | Create and cancel passed |
| Backend readiness while Collector was down | HTTP `200` |
| Collector ready after restart | `2026-10-22T15:49:54.849Z` |
| Collector health after restart | HTTP `200`, `Server available` |

The smoke test completed while the Collector was stopped. The business path did not wait for
telemetry export and the API remained ready, so E10 passes at local-drill scope.

After recovery, Prometheus reported every configured target as `UP`: Prometheus,
OpenTelemetry Collector, blackbox exporter, booking API readiness probe, node-exporter and
cAdvisor. Backend, Prometheus and Grafana health endpoints returned HTTP `200`.

## Limits and follow-up

- The Docker Desktop node-exporter and cAdvisor targets describe Docker's Linux VM rather than
  the physical Windows host.
- Repeat the drill on the shared Linux demo host and capture its timestamps before treating this
  as final demo evidence.
- Alert delivery remains unverified until the team configures the real Discord webhook.
